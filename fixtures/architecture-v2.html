Overview

The platform is split into a gateway, three domain services and a shared database. The gateway validates requests, applies rate limits and forwards each call to exactly one service. Each service writes to the shared database.

This document describes the target state for Q3. See the ADR on service boundaries for the reasoning.

Storage

Schema ownership

Every table has exactly one owning service. Other services read through views, never through the base tables. Each service writes to the shared database. Migrations run from the owning service's repository and are applied by the deploy pipeline before the new version receives traffic.

Retention

Request logs are kept for 30 days. Audit events are kept for seven years and are copied nightly to cold storage with pg_dump --data-only.

Operations

Deploys

Services deploy independently several times a day. A deploy that fails its health checks is rolled back automatically within five minutes.

On-call

One engineer per service is on call each week. Pages go to the owning team first and escalate to the platform team after fifteen minutes. Back to the overview.
